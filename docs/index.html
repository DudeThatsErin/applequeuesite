Data model

Three independent queues. An item is created by the extension, read once by your Shortcut, then acknowledged and deleted.

Note

{
  "id":          "uuid",
  "title":       "string",
  "body":        "string (Markdown)",
  "folder":      "string",
  "createdAt":   "ISO 8601",
  "attachments": [ { "name": "string", "url": "string", "mimeType": "string" } ]
}

Reminder

{
  "id":        "uuid",
  "title":     "string",
  "notes":     "string (Markdown)",
  "list":      "string",
  "url":       "string",
  "dueDate":   "ISO 8601 | \"\"",
  "priority":  "none | low | medium | high",
  "createdAt": "ISO 8601"
}

Event

{
  "id":        "uuid",
  "title":     "string",
  "notes":     "string",
  "calendar":  "string",
  "startDate": "ISO 8601",
  "endDate":   "ISO 8601",
  "allDay":    false,
  "location":  "string",
  "url":       "string",
  "invitees":  [ "string" ],
  "alerts":    [ 15, 60 ],
  "createdAt": "ISO 8601"
}

alerts is minutes before the start, deduplicated and sorted. Shortcuts cannot send calendar invitations, so any invitees also enqueue a reminder to CALENDAR_INVITE_REMINDER_LIST 24 hours before the event.

HTTP API

Every endpoint requires your per-install token, sent as an x-api-key header (or a ?key= query parameter for tools that can't set headers). Anything unauthenticated gets a 401.

MethodPathPurpose
GET/api/configWhich modules are enabled and their defaults. The extension self-configures from this.
GET/api/healthLiveness plus a token check — this is what Test connection calls.
Notes
POST/api/apple-notesQueue a note. title required.
GET/api/apple-notesList queued notes (the extension's queue view).
DELETE/api/apple-notesDrop items by id without creating them.
GET/api/apple-notes/pendingWhat the Shortcut fetches.
POST/api/apple-notes/ack{"ids": [...]} — created, remove them.
POST/api/apple-notes/uploadMultipart field file. Returns a durable attachment URL.
Reminders
POST / GET / DELETE/api/remindersSame shape as notes.
GET/api/reminders/pendingShortcut fetch.
POST/api/reminders/ackAcknowledge.
Calendar
POST / GET / DELETE/api/calendartitle, startDate, endDate required.
GET/api/calendar/pendingShortcut fetch.
POST/api/calendar/ackAcknowledge.
Optional
POST/api/places/autocomplete{"input": "…"} → suggestions. 503 when Places is off.
POST/api/ai/parseFree text → typed, titled, dated capture. 503 when AI is off.

Example: queue a reminder

curl -X POST https://YOUR-BACKEND.vercel.app/api/reminders \
  -H "x-api-key: $APPLE_QUEUE_API_KEY" \
  -H "content-type: application/json" \
  -d '{"title":"Renew passport","list":"Inbox","priority":"high"}'

Example: the Shortcut round trip

# 1 — what's waiting?
curl https://YOUR-BACKEND.vercel.app/api/reminders/pending \
  -H "x-api-key: $APPLE_QUEUE_API_KEY"

# 2 — created them; clear the queue
curl -X POST https://YOUR-BACKEND.vercel.app/api/reminders/ack \
  -H "x-api-key: $APPLE_QUEUE_API_KEY" \
  -H "content-type: application/json" \
  -d '{"ids":["",""]}'

Acknowledge or duplicate. /pending is not destructive — it returns the same items until you acknowledge them. That's deliberate, so a Shortcut that dies halfway doesn't lose your capture. It also means a Shortcut missing its ack step will create every item again on every run.

The whole configuration surface. Change any of these in your hosting project's settings and redeploy — no code edits, no reinstalling the extension.

Storage

Serverless functions get a throwaway filesystem, so nothing durable can live on disk.

Queues

A Redis/KV store — Vercel's Upstash integration is the default. The pending-item model is small and short-lived, so a key-value store is a better fit than a relational database. Neon, Supabase, or plain Postgres work too if you'd rather.

Attachments

Object storage: Vercel Blob by default, or any S3-compatible bucket (R2, S3, MinIO). Uploads are capped at 20 MB and limited to JPEG, PNG, GIF, WebP, HEIC, and PDF.

Filenames

Two names are tracked per attachment, on purpose:

Display name:        bowen_img.jpg          ← what you see in the note
Storage identifier:   3f9c…-bowen_img.jpg   ← what's actually stored

The stored name is prefixed with a random identifier so two uploads can't collide, and sanitized so a crafted filename can't escape its prefix. The display name is what the note shows.

Security model

Short version: the extension holds one token for one backend, and every provider secret stays server-side.

What the extension knows

Your backend URL and your Apple Queue token. Nothing else. There is no bundled key, no shared credential, and no secret you'd have to rotate for anyone but yourself.

What stays on the server

Your AI provider key and Google Places key, used only by your backend's own proxy routes. A browser extension is public code — anything shipped in it is published.

What the backend enforces

  • authentication on every queue read, write, acknowledge, and delete;
  • rate limits on the endpoints that proxy paid APIs;
  • upload size and MIME-type validation;
  • filename sanitizing and path-traversal rejection;
  • request-body validation on every route;
  • unguessable attachment URLs, and no directory listing.

Attachment URLs are capability URLs. They're long and random, but anyone holding one can fetch that file — which is exactly what makes them work inside a Shortcut. Don't attach anything you'd be unhappy to have readable by a link holder.

Rotating your token

Change APPLE_QUEUE_API_KEY in your project settings, redeploy, then update the extension's settings and the x-api-key header in each Shortcut. The old token stops working the moment the new deployment goes live.

Self-hosting

Same code, your own box. Worth knowing what changes.

Hosted on Vercel

Your backend runs on Vercel. Your computer does not need to stay on.

Self-hosted

Your backend runs on your own server or computer. That system must remain available for Apple Queue to work.

git clone https://github.com/DudeThatsErin/AppleQueue-Backend
cd AppleQueue-Backend
cp .env.example .env      # fill in the values from the setup wizard
npm install
npm run build
npm start

Then put it behind HTTPS with a real certificate. Browsers block extension requests to plain http://, and your Shortcut will be carrying your API key over the network.

Self-hosting also lets you keep the filesystem-backed storage instead of Redis and Blob, and to point AI_BASE_URL at a local Ollama — neither of which a serverless deployment can do.

Troubleshooting

Test connection fails

Check the URL has no trailing slash and no /api on the end, that it's https://, and that the key matches APPLE_QUEUE_API_KEY exactly — a trailing space pasted from a terminal is the usual culprit.

401 from the Shortcut

The header name is x-api-key, not Authorization. Shortcuts silently drops a header with an empty value, so confirm the value is actually there.

Items arrive twice, or forever

Your acknowledge step isn't running or is posting an empty ids array. Call /pending by hand after a run — if the item is still listed, the ack didn't land.

Queue is empty but I captured something

Confirm the module is enabled in /api/config, and that the extension is pointed at the backend you think it is. A capture against a stale URL fails quietly.

Shortcut runs but nothing appears

Usually a folder, list, or calendar name that doesn't exist on the device. Apple's actions don't always error on a bad name. Match your defaults to the real names, exactly.

Attachments don't attach

The note's attachments list has to be looped explicitly — a Shortcut that only reads body won't fetch them. Verify one URL in a browser first.

The automation never fires

Ask Before Running is still on, or the device was locked and low on battery. Run the Shortcut manually to prove the Shortcut itself works, then fix the automation.

AI parsing returns 503 or 429

503 means AI_ENABLED is off or the provider is unreachable. 429 means a parse is already in flight — requests are serialized on purpose.

Still stuck? Open an issue on GitHub. Include your /api/config response and the failing step — and redact your API key.
